# APCSP：从步骤数到复杂度表达 (From Steps to Big-O)

> **教学愿景**：把学生已经学过的搜索效率差别，进一步提升为对 `O(log n)`、`O(n)`、`O(n^2)` 的可视化表达与口头解释。
> **核心概念**：步骤增长（growth of steps）、对数复杂度、线性复杂度、平方复杂度、Big-O 表达。
> **适用人群**：AP Computer Science Principles 学生 / 高中编程初学者
> **预计时长**：20-25 分钟

---

## 📚 知识点总览

1. 算法复杂度描述的是输入规模变大时，步骤数如何增长
2. `Binary Search` 的“每次排除一半”对应 `log n`，记作 `O(log n)`
3. `Linear Search` 的“逐个检查”对应 `n`，记作 `O(n)`
4. 两层遍历或两两比较会产生 `n^2`，记作 `O(n^2)`
5. Big-O 记录的是增长级别，而不是精确秒数

---

## 🎯 教学目标

- 用自己的话解释算法复杂度是在描述什么
- 识别 `O(log n)`、`O(n)`、`O(n^2)` 的典型动作模式
- 能把“步骤数变化”翻译成表达式与 Big-O
- 能用 APCSP 风格语言解释三种复杂度的差别

---

## ⚠️ 常见误区

- **误区 1**：复杂度就是程序运行的秒数  
  **纠正**：复杂度描述的是步骤数随 `n` 增大时的变化趋势。

- **误区 2**：`O(log n)`、`O(n)`、`O(n^2)` 只是要背的符号  
  **纠正**：每一种复杂度都对应一种可观察的动作模式。

- **误区 3**：`O(n^2)` 只是“更慢一点的 O(n)`  
  **纠正**：`n` 翻倍时，`n^2` 的工作量会接近变成四倍，增长性质不同。

---

## 🧩 教学难点

- 学生容易把复杂度记号和实际算法动作脱节
- 学生容易会背 `O(n)` / `O(log n)`，但说不清为什么
- 学生对 `n^2` 的理解常停留在符号层面，缺少“面积暴涨”的直觉

---

## 🎬 五幕教学设计

### 场景 1：Opening Hook

- **核心问题**：当班级人数翻倍，哪类任务最容易失控？
- **交互设计**：
  - 展示三张任务卡：
    - 在有序名单里找一个学生
    - 在乱序名单里找一个学生
    - 检查全班每两个人是否有冲突
  - 切换班级人数 `n`
- **教师讲稿**：
  - “今天不再问哪一次更快，而是问：`n` 变大以后，步骤会怎样变？”
  - “复杂度的核心，不是结果对不对，而是增长方式是什么。”
- **一句话总结**：
  - `动作 -> 步骤 -> 表达式 -> Big-O`

### 场景 2：Search Replay

- **核心问题**：为什么已学过的搜索差别可以写成 `log n` 和 `n`？
- **交互设计**：
  - 并排显示 `Binary Search` 与 `Linear Search`
  - 支持切换规模、目标位置、单步 / 自动播放
- **教师讲稿**：
  - “每次排除一半，对应的是 `log n` 的增长。”
  - “逐个检查一遍，对应的是 `n` 的增长。”
- **一句话总结**：
  - `Binary Search -> O(log n)`，`Linear Search -> O(n)`

### 场景 3：Pair Comparison Grid

- **核心问题**：`n^2` 到底从哪里来？
- **交互设计**：
  - 用 `n x n` 学生比较矩阵表示“两两检查”
  - 切换班级人数
  - 逐步点亮被比较的格子
- **教师讲稿**：
  - “外层循环跑 `n` 次，内层也跑 `n` 次，所以总量是 `n * n`。”
  - “这就是平方复杂度最直观的来源。”
- **一句话总结**：
  - `nested loops -> n^2 -> O(n^2)`

### 场景 4：Complexity Translator

- **核心问题**：如何把动作模式翻译成复杂度表达？
- **交互设计**：
  - 三张翻译卡：
    - eliminate half each step
    - check one by one
    - compare every pair
  - 点击卡片后，显示表达式和 Big-O
  - 显示 `n doubles` 后的变化
- **教师讲稿**：
  - “Big-O 不是精确计步器，而是增长级别压缩器。”
  - “看到动作模式，就该想到对应的表达式。”
- **一句话总结**：
  - pattern first, Big-O second

### 场景 5：Final Summary

- **核心问题**：三种复杂度的教学收束如何表达？
- **交互设计**：
  - 三栏总结 `O(log n)`、`O(n)`、`O(n^2)`
  - 配套 `When n doubles` 对比
  - 课堂收束口头题
- **教师讲稿**：
  - “`O(log n)` 上升慢，`O(n)` 线性增长，`O(n^2)` 增长很快。”
  - “Big-O 描述的是输入规模增大时，步骤数如何增长。”
- **一句话总结**：
  - Big-O is about growth, not exact time.

---

## 🕒 教学节奏建议

1. **第 1-3 分钟**：Opening Hook，建立“为什么要写复杂度”
2. **第 4-8 分钟**：Search Replay，回收 `O(log n)` 与 `O(n)`
3. **第 9-14 分钟**：Pair Comparison Grid，讲清 `O(n^2)`
4. **第 15-19 分钟**：Complexity Translator，把动作翻译成表达式
5. **第 20-25 分钟**：Final Summary，形成结论和口头输出

- 两层循环为什么容易产生 `O(n^2)`？

## 🧠 本章金句

- **Big-O describes growth, not stopwatch time.**
- **If one loop gives you `n`, two full loops can give you `n^2`.**
- **When `n` doubles, different algorithms do not all get worse in the same way.**
