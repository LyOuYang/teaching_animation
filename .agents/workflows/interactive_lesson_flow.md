# 交互式教学课程工作流 (Interactive Lesson Flow)

本工作流定义了从"一个知识点"到"完整教学方案（文档+演示）"的标准过程。

## 阶段一：创意脑暴 (Teacher Role)
*目标：确定“怎么教”。*

1.  **加载技能**：
    AI 加载 `teaching_designer` skill。
    ```bash
    view_file .agent/skills/teaching_designer/SKILL.md
    ```

2.  **用户输入**：
    用户提供目标知识点（例如：“请设计一个关于‘傅里叶变换’的教学动画方案”）。

3.  **AI 输出**：
    AI 按照 skill 要求，输出 3 个可选方案。

4.  **决策点**：
    用户选择一个方案（或融合多个方案），并确认核心隐喻。

---

## 阶段二A：编写教学文档 (Teaching Document Writing)
*目标：将创意转化为面向教师的教学文档（教案）。*

1.  **加载技能**：
    AI 加载 `animation_developer` skill。
    ```bash
    view_file .agent/skills/animation_developer/SKILL.md
    ```

2.  **明确模式**：
    > **重要**：此阶段**只编写教学文档 MD**，不生成演示代码。
    > **文档性质**：面向教师的教案，强调"为什么这样教"和"如何引导学生"。

3.  **创建目录与文档**：
    *   AI 确定一个简洁的 `topic_slug`（如 `fourier_transform`）。
    *   AI 创建目录 `AP/data/[topic_slug]/`。
    *   AI 创建 `AP/data/[topic_slug]/[topic_slug].md`。
    文档必须严格遵循 `animation_developer` 第一部分定义的"教学文档"格式（Type A）。

4.  **评审门 (Gate)**：
    用户阅读教学文档，确认：
    - 知识点划分合理
    - 教学难点分析准确
    - 演示方案服务于教学目标
    **用户必须明确说"教学文档已确认，开始编码"才能进入下一阶段。**

---

## 阶段二B：生成演示代码 (Demo Implementation)
*目标：根据教学文档中的演示需求，生成可运行的 HTML 代码。*

1.  **明确模式**：
    > **重要**：此阶段**基于教学文档中提及的演示方案生成 HTML 代码**，不再修改教学逻辑。

2.  **提取演示需求**：
    AI 读取 `AP/data/[topic_slug]/[topic_slug].md`。
    AI 识别教学文档中每个"演示方案"部分：
    - 演示名称（将作为 HTML 组件名）
    - 演示目的
    - 交互设计（用户操作 → 观察现象）

3.  **编写代码**：
    AI 根据 `animation_developer` 第二部分的规范，生成 `AP/data/[topic_slug]/[topic_slug].html`。
    确保组件名称与教学文档中提及的名称一致。

4.  **验证**：
    打开生成的 HTML 文件，验证：
    - 每个演示能否正确体现教学目的
    - 交互是否符合教学文档描述

---

## 阶段三：迭代与优化 (可选)

根据验证结果，可选择以下路径：

*   **场景 A - 修改教案逻辑**：
    发现教案的交互设计或场景顺序需要调整。
    → 回到阶段二A，更新 MD，重新评审后进入阶段二B 生成新代码。

*   **场景 B - 仅调整视觉风格**：
    教案逻辑正确，但视觉效果（配色、布局、动画）需要优化。
    → 保持 MD 不变，直接修改 HTML 代码或重新生成（可指定不同风格）。

*   **场景 C - 推翻方案**：
    发现演示方案从根本上无法达到教学目标。
    → 回到阶段一，重新脑暴新的创意方案。
