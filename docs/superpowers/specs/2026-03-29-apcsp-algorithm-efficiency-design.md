# APCSP 算法效率课程设计

## 概述

- **主题**：算法效率（Algorithm Efficiency）
- **适用对象**：AP Computer Science Principles 学生，一对一授课
- **课时**：单课时，40-50 分钟
- **前置知识**：学生已学习 `linear search`、`binary search`，并见过简单搜索/排序例子
- **课程定位**：承接搜索章节，不额外扩展新算法，聚焦“同样能完成任务时，算法在输入规模增大后的步骤增长差异”

## 设计目标

本节课结束时，学生应能做到：

1. 用自己的话解释“算法效率”是在比较输入规模增大时，算法所需步骤如何变化。
2. 识别 `linear search` 的复杂度为 `O(n)`。
3. 识别 `binary search` 的复杂度为 `O(log n)`。
4. 看到搜索过程时，能用“逐个检查”与“每次排除一半”解释两者复杂度差异。

## 非目标

- 不系统展开 `O(1)`、`O(n^2)` 等更多复杂度类别。
- 不要求学生独立分析陌生算法的复杂度。
- 不以严格数学定义讲解大 O 记号。
- 不扩展到排序算法复杂度教学。

## 教学策略

本节课采用“**先看增长，再贴标签**”的组织方式：

1. 从学生已经掌握的搜索算法出发，先观察过程差异。
2. 用逐步放大的数据规模，让学生感受到步骤增长速度不同。
3. 在直觉稳定后，引入 `O(n)` 与 `O(log n)` 作为增长方式的标签。
4. 通过一对一口头追问确认学生能把过程画面与复杂度记号对应起来。

推荐沿用现有 `Search HQ` 教学语境，避免重新构建新的故事世界，以保证与上一节搜索课程自然衔接。

## 核心概念与误区

### 核心概念

- 两个算法都能完成同一任务，但效率可能不同。
- 算法效率关注的是输入规模变大时，步骤数如何增长。
- `linear search` 通过逐个检查完成查找，对应 `O(n)`。
- `binary search` 在有序数据中每次排除约一半候选，对应 `O(log n)`。

### 常见误区

1. **能做完就代表算法差不多好。**
   纠正：数据量较小时差异不明显，但规模变大后增长方式差异会被放大。

2. **`binary search` 更快只是因为“更高级”。**
   纠正：速度优势来自“每次排除一半”这一机制，而不是抽象上的“高级”。

3. **`O(n)` 和 `O(log n)` 只是要背的符号。**
   纠正：复杂度记号是在给步骤增长方式命名，必须和算法过程绑定理解。

4. **复杂度等于运行秒数。**
   纠正：本节课讨论的是增长趋势，不是具体机器上的精确计时。

## 课堂结构

### 1. 导入：从“会找”转向“效率”（约 5 分钟）

目标：把学生注意力从“算法能否完成任务”转向“规模变大后差异是否明显”。

建议提问：

- 如果有序列表里找一个数，`linear search` 和 `binary search` 都能成功，对吗？
- 如果列表只有 7 个元素，它们差别大吗？
- 如果列表有 7000 个元素，我们为什么还要比较它们？

### 2. 小规模并排比较（约 8-10 分钟）

目标：建立对两个搜索过程的直观差异。

教学动作：

- 选择一个有序列表，例如 `1-15`。
- 分别演示 `linear search` 与 `binary search`。
- 追踪“当前检查位置”和“剩余候选规模”。

建议追问：

- `linear search` 每一步做了什么？
- `binary search` 每一步做了什么？
- 哪一个更像“一个一个查”？哪一个更像“砍掉一大半”？

### 3. 放大规模，形成效率直觉（约 10-12 分钟）

目标：让学生看到“步骤增长速度不同”。

建议规模序列：

- `15`
- `31`
- `63`
- `127`

每轮先让学生预测，再观察结果。

建议追问：

- 如果数据翻倍，`linear search` 的步数会怎样变化？
- `binary search` 会不会也差不多翻倍？
- 当规模越来越大时，哪种算法的步骤增长更快？

### 4. 引入复杂度标签（约 8-10 分钟）

目标：在已有直觉上建立 `O(n)` 和 `O(log n)` 的识别。

教师说明：

- `linear search` 在最坏情况下可能要逐个检查整个列表，因此记作 `O(n)`。
- `binary search` 每次排除约一半候选，因此记作 `O(log n)`。

本段重点：

- 把 `O(n)` 理解为“输入变大时，步骤明显跟着变大”。
- 把 `O(log n)` 理解为“输入变大时，步骤也增长，但慢很多，因为每次都在砍半”。

### 5. 一对一口头确认（约 8-10 分钟）

目标：确认学生不是机械记忆，而是能把符号与过程对应。

建议提问：

- `linear search` 的复杂度是什么？
- `binary search` 的复杂度是什么？
- 为什么 `linear search` 是 `O(n)`？
- 为什么 `binary search` 是 `O(log n)`？

如果学生回答模糊，回到过程追问：

- 它每一步减少了多少工作量？
- 输入规模变大时，哪一个增长得更快？
- 这个复杂度标签描述的是哪件事？

## 教师话术

建议反复使用以下表达：

- 我们比较的不是这一次能不能找到，而是输入规模变大时，步骤怎么增长。
- `O(n)` 和 `O(log n)` 不是魔法符号，它们是在给增长方式贴标签。
- `linear search` 是一个一个检查，`binary search` 是每次排除一半，这就是复杂度不同的根源。

## 板书设计

### 标题

`Algorithm Efficiency: O(n) vs O(log n)`

### 左栏

- `Linear Search`
- checks one by one
- complexity: `O(n)`

### 右栏

- `Binary Search`
- eliminates about half each step
- complexity: `O(log n)`

### 底部总结

`Algorithm efficiency describes how the required steps grow as input size increases.`

## 一对一调整策略

### 学生反应快

- 减少演示轮数，增加预测问题。
- 在运行前先让学生猜规模放大后的变化。

### 学生反应慢

- 降低抽象层级，回到具体列表和具体步数。
- 暂时不强调复杂度术语，先确认其能说出“一个一个查”和“每次排除一半”。

### 学生只会背结论

- 要求每次说出复杂度时，必须补一句原因。
- 若只回答“因为老师说”，立刻追问算法每一步如何缩小问题。

## 成功标准

课程结束时，学生至少应能稳定说出以下两句中的核心含义：

- `linear search` 是 `O(n)`，因为最坏情况下可能要逐个检查整个列表。
- `binary search` 是 `O(log n)`，因为每次能排除大约一半候选，所以随着数据变大，步骤增长更慢。

## 后续衔接

本节课之后，可以顺势进入以下任一方向：

- 将 `O(n)` 迁移到遍历、筛选等“逐个处理”算法
- 继续扩展更多复杂度类别，如 `O(1)` 与 `O(n^2)`
- 回到 AP 风格题目中，练习根据描述识别算法效率
